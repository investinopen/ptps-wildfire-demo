# GitHub Pages site

A [homepage](index.qmd) introducing the project, the [fallback tools](fallbacks.qmd), the [dataset rescue status report](analysis/rescue-status.qmd), the [risk](analysis/risk.ipynb) and [wildfire overlap](analysis/fire_overlap.ipynb) notebooks, and the [detailed](#detailed) and [simplified](#simplified) [firefighter maps](#firefighter-maps) are published together as a [Quarto](https://quarto.org/) website, configured in [`_quarto.yml`](_quarto.yml). The rescue status report and the two notebooks live in [`analysis/`](analysis/#readme), along with the notebooks that aren't pages. The pages that run against live data (the rescue status report, the two notebooks, and the simplified firefighter map) are [re-executed daily](../.github/workflows/refresh-notebooks.yml) and whenever their code changes, so their live layers stay current. The site is [published](../.github/workflows/publish-site.yml) after each of those refreshes and whenever it changes, using the latest refreshed results rather than executing anything itself -- so if a data source is down, the pages just stay as of the last refresh. To preview locally, [install Quarto](https://quarto.org/docs/get-started/), then from the repository root run:

```sh
uv run quarto preview site
```

## Firefighter maps

Both in [`firefighter-maps/`](firefighter-maps/). The old `firefighter-map/` folder just redirects to the detailed one, for existing links.

### [Detailed](https://investinopen.github.io/ptps-wildfire-demo/firefighter-maps/detailed/)

A printable map for small/rural fire departments, in [`firefighter-maps/detailed/`](firefighter-maps/detailed/) -- a plain HTML page with its own layout, rather than rendered by Quarto.

Its water sources and road access (one-way streets, gates, dead ends, bridge weight limits) come from OpenStreetMap, in a PMTiles file built ahead of time rather than queried live:

1. [`build-access-tiles.yml`](../.github/workflows/build-access-tiles.yml) runs daily, and whenever the extractor changes, but skips building when neither Geofabrik's extract nor the code has changed since the last build. It downloads [Geofabrik](https://download.geofabrik.de/north-america/us.html)'s US extract (about 12 GB), filters it down with [osmium-tool](https://osmcode.org/osmium-tool/) to what the map uses, clips it to the map's bounds, extracts the layers with [`access_tiles.py`](../ptps_wildfire_demo/access_tiles.py) (which also works out where the dead ends are), and builds `osm-access.pmtiles` with [tippecanoe](https://github.com/felt/tippecanoe). It takes about an hour, and the tiles are uploaded as an artifact rather than committed.
1. [`publish-site.yml`](../.github/workflows/publish-site.yml) downloads the newest tiles built into the map's folder each time it publishes, and publishes again whenever a build finishes. A site change doesn't wait for a build, so it goes out with the last tiles built; changing what's in the tiles means adding the new layer or property first, then switching the map to it once a build has run.

So OSM edits take up to 3 days to show up on the map. [Geofabrik updates the extract daily](https://www.geofabrik.de/data/download.html) with OSM data up to about 20:20 UTC, ready around 00:20 UTC, and the build runs at 09:00 UTC: an edit made just before Geofabrik's cutoff shows up about 14 hours later, and one made just after waits about 38 hours, longer if Geofabrik's update runs late. The tiles' attribution says what date their data is from.

Where each feature's data comes from, and whether [Overture Maps](https://overturemaps.org/) is a good fit for it. Overture's hosted tiles are read straight from its site (see [`overture.js`](firefighter-maps/detailed/scripts/overture.js)). It's only used where it adds coverage, since its data updates monthly, while OpenStreetMap fixes show up within days.

| Feature                                                 | Source                                                                                                                        | Overture?                                                                                                                    |
| ------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| Buildings, contiguous US                                | [CarbonPlan](https://carbonplan.org/research/climate-risk)'s risk tiles, built on Overture's footprints                       | Yes, already: the risk scores come with them                                                                                 |
| Buildings, Alaska and Hawaii                            | Overture                                                                                                                      | Yes: OpenStreetMap has almost none outside of towns, while Overture adds Microsoft's and Google's machine-learned footprints |
| House numbers                                           | Overture, plus OpenStreetMap's where Overture has none                                                                        | Yes: Overture has far more in most rural areas, from the National Address Database and state/county data                     |
| Roads, road names, route numbers                        | OpenStreetMap, via [OpenFreeMap](https://openfreemap.org/)                                                                    | No: Overture's US roads are mostly OpenStreetMap's                                                                           |
| Road access (gates, dead ends, one-ways, weight limits) | OpenStreetMap, via the access tiles                                                                                           | No: Overture's roads leave out the tags and connections these are built from                                                 |
| Water sources and hydrants                              | OpenStreetMap, via the access tiles                                                                                           | No: what Overture has of these comes from OpenStreetMap                                                                      |
| Lakes, rivers, state lines                              | OpenStreetMap, via OpenFreeMap                                                                                                | No: Overture's are from OpenStreetMap too                                                                                    |
| State in the sidebar heading                            | [Census cartographic boundaries](https://www.census.gov/geographies/mapping-files/time-series/geo/cartographic-boundary.html) | No: already complete                                                                                                         |
| Place search                                            | [Photon](https://photon.komoot.io/) (OpenStreetMap)                                                                           | No: Overture's places are mostly OpenStreetMap's, and it has no search service                                               |
| Town labels                                             | OpenStreetMap, via OpenFreeMap                                                                                                | No: same as place search                                                                                                     |
| Hillshade                                               | [Mapterhorn](https://mapterhorn.com/)                                                                                         | No: Overture has no elevation data                                                                                           |
| Flame length                                            | USFS Wildfire Risk to Communities                                                                                             | No: Overture has no fire data                                                                                                |

"Print an area…" in its sidebar makes a printable atlas of a rectangle drawn on the map, all in the browser: an index page, then one US Letter landscape page per piece of a grid over the area, each with the sidebar's legend, a key map, and the numbers of the pages next to it. The scale defaults to 1:4,000; scales too zoomed out to show house numbers, dead ends, and gates (zoom 15) at the area's latitude can't be picked. The drawing is in [`atlas-draw.js`](firefighter-maps/detailed/scripts/atlas-draw.js), the grid in [`atlas-grid.js`](firefighter-maps/detailed/scripts/atlas-grid.js), and each page is drawn by the map itself and saved as an image ([`atlas-capture.js`](firefighter-maps/detailed/scripts/atlas-capture.js)), one at a time, about two seconds each. Pages with no roads or buildings are left out.

To preview the map locally, get a copy of the tiles (or [build some](../.github/workflows/build-access-tiles.yml) from a smaller extract, like a state's), then serve `site/` with a server that supports the byte-range requests PMTiles uses, rather than Quarto's preview:

```sh
curl -o site/firefighter-maps/detailed/osm-access.pmtiles https://investinopen.github.io/ptps-wildfire-demo/firefighter-maps/detailed/osm-access.pmtiles
npx http-server@14.1.1 site -c-1
```

### [Simplified](https://investinopen.github.io/ptps-wildfire-demo/firefighter-maps/simplified/)

A simplified map for navigation ([#22](https://github.com/investinopen/ptps-wildfire-demo/issues/22)): the roads around a rural town drawn as a graph of intersections and the roads between them, each drawn with its length proportional to its driving distance, colored by its steepest grade, and with sharp turns, dead ends, gates, and addresses marked. Roads come from OpenStreetMap via [OSMnx](https://osmnx.readthedocs.io/), and elevation from [Mapterhorn](https://mapterhorn.com/)'s terrain tiles. It's [`firefighter-maps/simplified/index.qmd`](firefighter-maps/simplified/index.qmd), which just shows the results -- change the place passed to `SimplifiedMap.build()` to move it. Its code is in [`ptps_wildfire_demo/simplified_map/`](../ptps_wildfire_demo/simplified_map/), starting from [`pipeline.py`](../ptps_wildfire_demo/simplified_map/pipeline.py) (which has the settings), with tests in [`tests/test_simplified_map.py`](../tests/test_simplified_map.py).
